5 · 過程中撞到、並且改好嘅三個數學錯

  1. hue 目標表用角度線性插值 → 插出垃圾。 palette 由 L25(a−10.2,b+5.0) 插值去 L55(a−26,b−8.9) 途中會掠過中性軸， 目標色相喺 ±180° 附近。實測 L=35.79 讀到 83.4°、L=36.04 讀到 −144.4°（差 0.25 L 跳 132°）。 改：LUT 存 Cartesian 目標向量，用嗰陣先 atan2。
  2. 「旋向目標色相」喺對極有分支切。 任何「圓 → 旋轉量」嘅連續奇映射都一定要喺對極為 0 （Δh(180) = −Δh(−180) = −Δh(180) ⇒ Δh(180)=0）。 實測 33³ LUT 嗰度出現 168/255 硬跳（會 tearing）。 改：Δh = K·sin(Δ)，係最簡單而且 C¹ 連續嘅解。
  3. 低 chroma 像素嘅方向跟咗「來源 hue」，而嗰個方向喺中性軸上未定義。 C' = C + s(Ct−C) 即係 C→0 嗰陣 chroma 會被抬去 s·Ct（約 20）， 方向如果仲用嚟源 hue，跨過中性軸就成個輸出翻轉。 改：w = smoothstep(0, 7, C)，低 chroma 嗰陣方向收去目標色相。
改完呢三樣：LUT 相鄰格最大跳 168 → 68/255；LUT vs 直接計 p99 由 42 → 2.26/255。

8 · 用家操作（app 入面）

  1. 【方向預覽 DIRECTIONS】→ 揀導演 → 落 look
  2. 【拖框 key】：喺預覽圖拖一個框框住塊面（自動框只係起步點，實測會框錯背景）
  3. 【保護膚色】checkbox + 【膚保】桿（100% = 色相彩度完全還原，淨留 tonal 變化）
  4. 【色度降噪】：grade 之前嘅 L 導引邊緣保留平滑，專消逐像素判定整出嚟嘅斑點
  5. 【融合】桿 = look 力度（0% = 原圖）
已知限制：key 係靜態矩形，無追蹤。搖鏡／演員行開要重新框，或者分段框。 真正的做法係 loaded matte（Baselight/Resolve 嘅 tracker），要落去就要接追踪器。
